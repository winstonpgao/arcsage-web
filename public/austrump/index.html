End to End Journey

What happens to each email in seconds

1. Arrives

Email arrives. System cleans message text, loads full conversation history, identifies sender, and detects language (EN/CN).

2. Recalculate

All 11 Dimensions are re-evaluated. Score adjusts based on new information extracted from this message.

3. Decision

Not Ready: Ask targeted questions (max 2).
Ready: Congratulate buyer & notify team.

4. Handover

Internal notification sent to agents with readiness flags, summary, contact details, and next steps.

端到端旅程

每封邮件在几秒钟内发生的事情

1. 收到

邮件收到。系统清理文本，加载完整历史，识别发送者，检测语言(中/英)。

2. 重新计算

所有11个维度重新评估。分数根据提取的新信息调整。

3. 决策

未准备好: 提针对性问题(最多2个)。
准备好: 祝贺买家并通知团队。

4. 移交

发送内部通知给代理，包含准备度标记、摘要、联系方式和下一步。

Edge Cases and Safety

Outperforming simple bots with strict guardrails

Robustness

  • Phone Validation: Retries invalid numbers twice, then stops.
  • Impossible Budgets: Flags as "Unknown" rather than erroring.
  • Jokes/Off-topic: Handled calmly without breaking character.

Safety Guardrails

  • Illegal Requests: "Is this area safe?" -> Declined safely.
  • Financial Advice: Explicitly avoids giving loan advice.
  • Internal Flags: Risky conversations flagged for human review.

边缘情况与安全

严格护栏超越简单机器人

稳健性

  • 电话验证: 重试无效号码两次，然后停止。
  • 不可能的预算: 标记为“未知”而不是报错。
  • 玩笑/离题: 冷静处理，不脱离角色。

安全护栏

  • 涉及法律或安全承诺的请求，例如“这个区安全吗？” → 系统只提供中立、事实性信息，避免作出不当判断。 "这区安全吗？" -> 安全拒绝。
  • 财务建议: 明确避免给出贷款建议。
  • 内部标记: 风险对话标记供人工审查。

Human Handoff & Helper Mode

Clear rules for escalation

Helper Mode Workflow

  1. If buyer asks for a person, system sends one confirmation.
  2. "Human Requested" flag recorded.
  3. System enters Helper Mode (stops replying).
  4. Scoring continues quietly for internal awareness.
  5. Full context sent to team when buyer becomes ready.

人工移交与辅助模式

清晰的升级规则

辅助模式流程

  1. 如果买家要求人工，系统发送一条确认。
  2. 记录“人工请求”标记。
  3. 系统进入辅助模式（停止回复）。
  4. 评分继续在后台进行，供内部了解。
  5. 当买家准备好时，收集到的完整相关信息发送给团队。
